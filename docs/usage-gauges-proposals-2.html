Pastille partie 2

Jauges de quota — pastille pleine, et des alternatives aux barres

Deux questions dans ce doc. Partie 1 : la pastille creuse se perd sur les pistes de 3 px du header et sur les anneaux du mobile. Voici 9 variantes, dont le rond blanc plein, chacune rendue sur les 4 surfaces réelles (header desktop, bandeau comptes, header mobile, popover). Partie 2 : 8 systèmes qui remplacent complètement les barres, rendus sur le header desktop, le bandeau comptes et le mobile.

« Blanc » veut dire la couleur du texte du thème : blanc sur les thèmes sombres, presque noir sur Daylight et Cupertino. Change de thème en haut pour le voir. Dans la partie 2, le sélecteur Pastille partie 2 choisit quel style de pastille les nouveaux systèmes utilisent pour le rythme.

Pour répondre : un ID de pastille et, si tu veux changer de système, un ID de la partie 2, par exemple « P2 » ou « R2 pour le bandeau, R1 pour le header, avec P3 ».

1La pastille de suivi

Même barre, même anneau, seule la pastille change. Le cas qui compte : une pastille sur une piste vide (on est en avance sur le temps, la barre s'arrête avant) et une pastille sur le remplissage (on va trop vite). La situation « Mixte » montre les deux.

2Remplacer les barres

D'autres façons de montrer les trois fenêtres (5h, semaine, plafond par modèle) dans les trois surfaces compactes. Le popover de détail garde ses barres dans tous les cas : c'est l'endroit où on lit les chiffres exacts et les resets, il a la place. Chaque système garde le rythme (la pastille choisie en haut, ou son équivalent), la sévérité (vert / ambre / rouge) et le pourcentage lisible sans survol, sauf mention contraire.

Mes recommandations

Pastille → P2 « Plein + liseré ». C'est le rond plein que tu demandes, avec un fin anneau de la couleur du fond autour qui le détache de n'importe quel remplissage. Il se voit sur la piste vide (rond clair sur piste sombre) comme sur la barre colorée (découpe nette), et sur les anneaux mobiles il fait une vraie bille. Si c'est encore trop petit sur ton écran, P3 est la même en plus grosse. Le rond plein sans liseré (P1) bave sur le vert et l'ambre clairs, surtout en thème sombre.

Si tu changes de système :

— R1 « Anneaux partout » est le changement le plus sûr : le header desktop adopte les anneaux du mobile, une seule grammaire visuelle partout, et le code existe déjà (UsageRings).

— R2 « Cadran d'activité » est le plus compact et le plus élégant pour le bandeau comptes : un seul symbole de 24 px par compte au lieu de trois anneaux. Il demande d'apprendre l'ordre des anneaux (extérieur = 5h).

— R4 « Pilules remplies » est le plus lisible : le chiffre est dans la jauge elle-même, et le remplissage reste en fond.

Ce que ça touche dans le code

Partie 1 : uniquement PaceMark et Ring dans app/UsageMeter.tsx et les règles .um-pace / .ur-pace de app/claude.css. Le cercle reste un SVG (pour garder la même taille à tous les zooms) ; le liseré est le même --um-surface qu'aujourd'hui.

Partie 2 : la cellule runtime (UsageMeter en mode runtime) et UsageRings (bandeau comptes + mobile). Aucune donnée nouvelle : tout vient de utilization, resetsAt et paceFraction(). R1 réutilise Ring tel quel ; R2, R3, R6 et R8 sont des SVG neufs ; R4, R5 et R7 sont surtout du CSS.
